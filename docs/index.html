why offline

Your phone is the datacenter.

no internet

Runs with airplane mode on

The AI model (stable-diffusion.cpp) and the video renderer (ffmpeg) both run on your device. After the one-time setup, nothing ever leaves your phone.

no limits

Generate as much as you want

There is no server metering your prompts. 3 videos or 300 — the only cost is your battery and your patience.

no accounts

Private by design

No sign-up, no API keys, no telemetry. Your prompts and videos never exist anywhere but on your phone.

low-end friendly

Built for weak hardware

Uses a distilled SD-Turbo model (4 steps per image), a tiny TAESD decoder, and quantized GGUF weights to fit in ~2 GB of RAM.

how it works

Prompt in, MP4 out — all on-device.

01

You describe the video

Type something like "a peaceful waterfall in a magical forest, fireflies at dusk, cinematic". Pick the number of scenes, resolution and camera motion in the web UI.

02

An AI paints the keyframes — on your phone

stable-diffusion.cpp generates one image per scene, each with a slightly different shot (wide, close-up, golden hour) so the video feels like it's traveling through the scene.

03

ffmpeg turns stills into cinema

Each keyframe gets camera motion — smooth zooms and pans — then scenes are blended together with crossfades into a final H.264 MP4, ready for your gallery or Reels.

install

Three commands, one time.

Install Termux (from F-Droid, not Play Store)

Termux is the terminal that lets the AI engine run on Android. The Play Store version is outdated and broken — get it from f-droid.org/packages/com.termux. You'll also need ~4 GB free storage and Wi-Fi for the one-time model download.

Clone and set up

Paste this into Termux. Setup compiles the AI engine (10–30 minutes — keep the charger plugged in) and downloads the model you pick.

termux
git clone https://github.com/pj9811193-create/local-ai-video-studio.git ~/aivideo cd ~/aivideo && bash setup.sh

Start creating

Setup opens your browser at the studio. From now on, this is the only command you need — internet not required.

termux
bash start.sh # → http://localhost:8080
Interrupted setup? Downloads resume — just run bash setup.sh again. No model yet? The app runs in demo mode so you can test the whole video pipeline instantly.

The honest part: this is not Sora. Frame-by-frame movie models need a desktop GPU with gigabytes of VRAM — that physics doesn't bend for phones. What you get is AI-generated cinematic scene videos: real on-device AI images, animated with camera motion and crossfades. That's the honest maximum for fully-offline, unlimited, free generation on low-end hardware. Keep the phone plugged in while it works.
faq & troubleshooting

Common questions.

Generation dies mid-way on Android 12+
Android silently kills long-running processes. Fix it once with ADB from a PC: adb shell "/system/bin/device_config set_sync_disabled_for_tests persistent; /system/bin/device_config put activity_manager max_phantom_processes 2147483647"
The setup build was killed / ran out of memory
Re-run bash setup.sh — the build resumes where it stopped. On very weak phones, open setup.sh and change JOBS=2 to JOBS=1, then retry.
Termux crashes when generating
Lower the load: pick 3 scenes at 320 resolution, install the Q4_0 model (setup option 2), close other apps, and keep the screen on while generating.
Can it do 9:16 vertical / longer videos?
The engine generates square scenes today; cropping to vertical or stacking more scenes is easy — it's all open source on GitHub, and PRs are welcome.
Is it really free? Where's the catch?
The code is MIT-licensed; the app uses open-source components (stable-diffusion.cpp, ffmpeg, Flask). The only costs are your battery, storage (~2.5 GB) and time. Note the SD-Turbo model itself is licensed for non-commercial research use — check the license before commercial work.
